# InterviewCopilot 接口测试用例

基线：2026-10-29 · glm-4-flash · 51 篇真实笔记（609 段向量）· 全部用例在真实环境手工执行过。

## 0. 环境准备

```bash
# 启动（key 从环境变量读，笔记目录自动导入）
set ZHIPUAI_API_KEY=你的key          # Windows，或 setx 永久
java -jar target/interview-copilot-0.1.0-SNAPSHOT.jar --rag.auto-import-dir=D:/你的笔记目录

# 健康检查通过后再执行后续用例
curl -s localhost:8090/api/health
```

> **Git Bash 中文陷阱**：直接在命令行写中文 JSON 会 400（编码问题）。用 UTF-8 文件 + `--data-binary`：
> ```bash
> printf '{"question":"什么是JMM"}' > q.json
> curl -s -X POST localhost:8090/api/chat -H "Content-Type: application/json" --data-binary @q.json
> ```

## 3. POST `/api/ask/stream` — 直连流式（SSE）

事件协议：`token*` → `done` | `error`。`token` 的 data 是**裸文本**（Spring 对 String 载荷不做 JSON 编码），`done` 的 data 是 JSON（`{"latencyMs":...}`）。

| 编号 | 场景 | 请求 | 预期 |
|---|---|---|---|
| T-ASKS-01 | 正常流式 | `{"question":"一句话说明什么是JMM"}` | 先收 N 个 `token` 事件，最后一个 `done`；无 `sources` 事件；拼接 token 为完整回答 |
| T-ASKS-02 | 空 question | `{"question":""}` | 仅一个 `error` 事件后连接关闭 |

## 附：SSE 解析注意事项（前端/脚本消费方）

- 按 `\n\n` 切事件块，`event:`/`data:` 前缀解析；`event:` 冒号后**无空格**。
- `token` 的 data 是裸文本，`sources`/`done`/`error` 的 data 是 JSON——解析需 `try { JSON.parse } catch { 原样字符串 }`。
- 事件名冒号后无空格是 Spring `SseEmitter` 的序列化格式，与 W3C 规范（允许冒号后一个可选空格）兼容。
